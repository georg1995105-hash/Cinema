# Постоянная подпись Android

Начиная с версии 0.4.0, сборка поддерживает единую подпись для следующих выпусков. В публичный репозиторий **нельзя** загружать приватный ключ или пароль.

Секреты GitHub Actions:
- `ANDROID_KEYSTORE_BASE64` — Base64 содержимого проверенного файла PKCS12 (без переносов строк).
- `ANDROID_KEYSTORE_PASSWORD` — пароль хранилища и ключа.
- `ANDROID_KEY_ALIAS` — `kino`.

Ключ RSA-3072 / PKCS12 создан 17 ноября 2026 года. **Первая пара файл–пароль оказалась несогласованной**, поэтому подписанная сборка [44103082880](https://github.com/georg1995105-hash/Cinema/actions/runs/44103082880) завершилась ошибкой на шаге packageRelease. Этот ключ использовать нельзя.

Создана новая пара, независимо проверенная через Java keytool и cryptography. Контрольный SHA-256 отпечаток публичного сертификата (не приватного ключа): `1D:B5:04:F6:6F:A3:9C:F5:1F:EE:FA:B7:27:F5:B8:B2:29:BA:EF:08:A5:AE:2D:E8:0D:A0:51:91:51:4F:93:CB`.

**Обновить в GitHub оба секрета:** `ANDROID_KEYSTORE_BASE64` и `ANDROID_KEYSTORE_PASSWORD`; `ANDROID_KEY_ALIAS=kino` оставить. До этого CI не должен публиковать APK. Настраивать секреты только через защищённый интерфейс GitHub; значения не добавлять в код, историю коммитов и журнал.

Если ключ отсутствует, CI выполняет тесты, но не публикует подписанный APK. Этот случай не замещается случайной отладочной подписью.

После настройки всех трёх секретов:
1. Запустить сборку ветки main.
2. Проверить `apksigner verify --print-certs` и контрольную сумму.
3. Опубликовать APK как стабильную версию и проверить обновление следующей версией под тем же ключом.
4. Проверить на планшете сохранение истории и зеркал при установке поверх предыдущей **стабильной** версии.

Старые отладочные APK v0.1–0.3.1 подписаны иным ключом. Использовать их как основание для обновления без удаления невозможно: это ограничение механизма подписи Android. Нельзя подменять приватные ключи или скрытно обходить проверку подписи.

Резервную копию исправленного файла PKCS12 и пароль хранить вне публичного GitHub. Утеря ключа лишит возможности выпускать совместимые обновления.


## Подтверждение постоянной подписи версии 0.4.0

17.11.2026 секреты ключа и пароля были заменены на согласованную пару и выполнилась [успешная проверка](https://github.com/georg1995105-hash/Cinema/actions/runs/44105474099). В GitHub Actions прошло: testDebugUnitTest, assembleDebug, assembleRelease, apksigner verify, загрузка артефакта. Публичный сертификат SHA-256: `1db504f66fa39cf51feefab727f5b8b229baef08a5ae2de80da05191514f93cb`.

Первый подписанный [стабильный релиз 0.4.0](https://github.com/georg1995105-hash/Cinema/releases/tag/v0.4.0) опубликован. Для всех следующих версий нужно **сохранять те же три секрета** и проверять отпечаток сертификата. Первая установка с прежних отладочных сборок может потребовать удаления старой. Сквозное обновление между двумя стабильными версиями на планшете ещё не проверено.
